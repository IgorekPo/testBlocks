ПАПИРУС + КАТАЛОГ — ОБНОВЛЁННАЯ СБОРКА

Структура:
- index.html              главная страница с шестью папирусными секциями
- script.js               исходный механизм перелистывания главной
- catalog.html            отдельная HTML-страница каталога
- catalog-page-turn.js    тот же внешний page-curl для страниц каталога
- catalog-products.js     фильтры и внутренняя книга карточек с таким же 3D page-curl
- catalog.css             оформление отдельной страницы каталога
- style.css               базовые стили папирусных страниц
- page-transition.js      плавный переход между index.html и catalog.html
- images/                 папка для папирусных текстур

ЧТО ИЗМЕНЕНО
1. Внутренние страницы карточек больше не переворачиваются обычным CSS rotateY.
   При перелистывании делается снимок HTML-страницы карточек через html2canvas,
   затем эта текстура накладывается на сетку Three.js и деформируется тем же
   алгоритмом, что и папирусные секции в testBlocks.
2. Внутреннюю страницу можно тянуть мышью или пальцем: лист деформируется
   вслед за горизонтальным движением. Кнопки-стрелки используют тот же эффект.
3. Внешняя страница каталога (фильтры + карточки) остаётся обычной папирусной
   секцией и перелистывается исходным механизмом из testBlocks.
4. Перед началом переворота каждой секции добавлена пауза 12svh. После полного
   открытия также остаётся дополнительная пауза 12svh перед обратным закрытием.
   Поэтому при входе в секцию лист не появляется мгновенно, и при возвращении
   назад не начинает закрываться сразу. Каталог дополнительно сохраняет
   увеличенное время просмотра до перехода на третью пустую секцию.
5. Главная страница и её script.js не менялись.

КАК УСТАНОВИТЬ
1. Распакуй архив в папку проекта.
2. Сохрани свою папку images и проверь, что в ней находятся:
   images/papyrus-beige.webp
   images/papyrus-green-beige.webp
   Если файлов нет, скрипт проверит и загрузит оригинальные изображения
   напрямую из raw.githubusercontent.com/IgorekPo/testBlocks/main/images/.
   Тот же найденный URL используется и как CSS-фон, и как текстура Three.js.
3. Открой index.html через Live Server.
4. Перелистай до третьей секции и нажми «Каталог».

ЗАВИСИМОСТИ
- Three.js r170 загружается с jsDelivr для внешнего и внутреннего 3D-листания.
- html2canvas 1.4.1 загружается с jsDelivr и нужен только для создания снимка
  содержимого карточной страницы перед её физическим 3D-переворотом.
- WebGL-canvas внутренней книги создаётся динамически ПОСЛЕ снимка HTML и
  временно удаляется из DOM на время следующих снимков. Это предотвращает
  конфликт типов контекста Canvas2D/WebGL в Chromium и других браузерах.
Поэтому для обоих 3D-эффектов требуется подключение к интернету.

КАРТОЧКИ
В каталоге 16 демонстрационных карточек. Сетка: 4x2 на ПК, 3x2 на планшете,
2x2 на телефоне. Фильтры по цвету и мясу комбинируются.
Названия и упаковки пока демонстрационные — их можно заменить позже.


ВНУТРЕННЯЯ КНИГА КАТАЛОГА — ПЕРЕЛИСТЫВАНИЕ
- Лист с карточками использует фон ./images/papyrus-beige.webp.
- Под ним лежит следующая страница с новой группой карточек.
- Во время перетягивания Three.js деформирует сетку листа непрерывно вслед за движением мыши/пальца: чем дальше тянуть, тем больше следующая страница открывается под листом.
- Если отпустить до 22% ширины страницы, лист вернётся назад; после 22% — завершит переворот.
- Стрелки выполняют тот же 3D-переворот автоматически.
- Убраны CSS color-mix() из карточек: html2canvas 1.4.1 не во всех браузерах корректно обрабатывает современные цветовые функции, из-за чего снимок листа мог не создаваться и внутренний page-curl не запускался.

ИСПРАВЛЕНИЕ WEBGL CONTEXT
- В HTML больше нет заранее созданного canvas для внутренней книги. Вместо него
  находится пустой контейнер #catalogBookCurlHost.
- После того как html2canvas завершил снимок карточной страницы, catalog-products.js
  создаёт новый canvas и передаёт его Three.WebGLRenderer.
- Перед следующим html2canvas-снимком этот WebGL-canvas временно извлекается из DOM
  и возвращается после снимка. Сам WebGL-контекст при этом сохраняется.
- Внешний #page-turn и внутренний canvas остаются разными элементами и имеют
  независимые WebGL-контексты.
